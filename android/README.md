# 電力モニタ (Android)

Cube のダッシュボードを全画面で開き、家にいる間に履歴を端末へ貯めて、
外では貯めた履歴を見るためのアプリ。

依存ライブラリはゼロ。AndroidX も使っていない。権限はネットワークと
起動時の再開（定期同期を再起動後も続けるため）だけで、位置情報もストレージも要らない。

## 受け取り方

`main` に `android/` の変更が入ると GitHub Actions がビルドし、固定のリンクに置き直す。

https://github.com/nekomami-create/cubeJ1/releases/download/apk-latest/cubej1-monitor.apk

スマホの Chrome で開けばそのままダウンロードしてインストールできる
（提供元不明のアプリの許可は必要）。デバッグ署名なので、前の版の上から更新できる。

## 画面

WebView 1枚に2つのページを出し分ける。

| | 出すもの |
|---|---|
| 家にいるとき | Cube のダッシュボードそのもの（ライブ） |
| 外にいるとき | 端末に貯めた履歴（`assets/history.html`） |

どちらを出すかは **Cube に `/healthz` を投げて決める**。Wi-Fi の名前を読む方式だと
位置情報の権限が要るうえ、知りたいのは「Cube が生きているか」そのものなので。
起動時の確認は2.5秒で、届かなければ黙って履歴に落ちる。

右下に浮いたボタンで行き来する（ライブ画面では「履歴を見る」、履歴画面では
「ライブ画面へ」）。ライブ画面は Cube 自身のページなのでアプリからは手を入れず、
ボタンはネイティブで重ねてある。「ライブ画面へ」で Cube に届かなかったときは、
その旨を出して履歴に留まる。

外から「今何W」は見られない。外で見えるのは**最後に家にいた時点までの履歴**。

### 履歴画面

上から、年 → 月 → その月のカレンダー → 選んだ日のグラフ → CSV。

- **年**は ‹ › で切り替え、横に年間の合計 kWh
- **月**は12か月を2段で並べ、それぞれ月の合計 kWh。記録のない月は押せない
- **カレンダー**は日曜始まりで、各日の kWh。30分ごとの値が欠けている日は薄い字
- **日のグラフ**は、30分平均の棒と1分ごとの線を同じ軸（W）に重ねる

棒は kWh だが W に直してある。30分あたりの kWh に 2000 を掛けるとその30分の平均 W に
なるので、1分ごとの瞬時値と同じ量として正しく重なる。1分ごとの値に5分以上の穴があれば
線を途切れさせる（棒の上をまっすぐ結ぶと、無いデータがあるように見えるため）。

### CSV

履歴画面のいちばん下から書き出す（戻るボタンのメニューからも書き出せる）。
保存先はシステムの保存画面で選ぶので、ストレージ権限は要らない。

| | 範囲 | 列 |
|---|---|---|
| 30分ごと | この月 / すべて | `date, slot, time, use_kwh, cum_kwh` |
| 1分ごと | この月 / すべて | `epoch, iso_local, power_w, current_r_a, current_t_a` |

ファイル名は `cubej1-halfhour-2026-10.csv`（この月）や `cubej1-minute-20261024.csv`（すべて）。

### メニューと設定

戻るボタンでメニューが出る（今すぐ同期 / ライブと履歴の切り替え / CSV / 接続先を変更）。
画面に設定ボタンを置くと、ダッシュボードのレイアウトに割り込むため。

初回起動で Cube の IP を聞かれる。ポートの既定は 8080。ブラウザのアドレスバーから
URL ごと貼り付けても受け付ける。「Cube を探す」を押すと、この端末の IPv4 から /24 を割り出して
1〜254 に TCP 接続を試し、`/healthz` が `ok` を返したものだけを候補に出す（およそ3秒）。
DHCP で IP が変わると届かなくなるので、ルーターで固定しておくこと。

## 履歴を貯める

`JobScheduler` の定期ジョブ（15分間隔、Wi-Fi のときだけ、再起動後も継続）が
Cube から引いて SQLite に入れる。アプリを開いたときにも1回走る。常駐サービスには
していない（通知が出っぱなしになり、数分に1回の HTTP のために前面サービスは釣り合わない）。

| 取るもの | Cube 側の保持 | 端末側の保持 |
|---|---|---|
| 30分ごとの使用量 | 400日 | 消さない |
| 1分ごとの電力 | 5日 | 90日 |

初回だけ400日分を取り、以降は直近10日分だけ取り直す。1分ごとの値は Cube が5日分しか
持たないので、**5日に1回は家で同期しないと穴があく**。

## 署名鍵

`android/app/debug.keystore` を**意図的にコミットしてある**。alias もパスワードも
Android 慣例の `androiddebugkey` / `android`。

署名設定が無いと Gradle はビルドするマシンでデバッグ鍵を作る。CI は毎回まっさらな
仮想マシンなので毎回別の鍵になり、Android は前回の install を「パッケージ競合」として
上書きを拒む。実際にそれを踏んだ。鍵を固定したので、CI の APK と手元でビルドした APK は
互いに上書きできる。

パスワードが慣例値なので、ファイルを取れば誰でも使える。それでも許容できるのは、
Google Play がこの署名の APK を受け付けず、配布経路が手動インストールしか無いため
（悪用するには結局持ち主に手で入れさせる必要がある）。

### 配布用の鍵を足すとき

`build.gradle` は触らなくていい。リポジトリの Secret に置けば release ビルドがそれを使い、
無ければデバッグ鍵に落ちる。

| Secret 名 | 中身 |
|---|---|
| `RELEASE_KEYSTORE_BASE64` | キーストアを base64 にしたもの |
| `RELEASE_KEYSTORE_PASSWORD` | ストアのパスワード |
| `RELEASE_KEY_PASSWORD` | 鍵のパスワード |
| `RELEASE_KEY_ALIAS` | 鍵のエイリアス |

### どの鍵で署名されたか確かめる

v1 署名も有効にしてあるので、APK から直接読める。ワークフローの "Which key signed it" が
毎回これを出す。

```
keytool -printcert -jarfile cubej1-monitor.apk
```

今のデバッグ鍵は
`D2:B4:E7:10:56:D0:4F:5F:5A:EF:FD:EE:A4:8C:38:40:5B:81:F6:13:26:62:BE:5A:14:C6:2E:9C:34:2A:01:C7`。

鍵が変わると既存の install は更新できず、一度だけアンインストールが要る。30分ごとの記録は
Cube に400日分あるので、入れ直して家で1回同期すれば戻る。戻らないのは5日より古い1分ごとの値だけ。

## 手元でビルドする

```
cd android
gradle assembleDebug     # Gradle 8.7 以上と JDK 17。Android Studio で開いてもよい
```

出力は `app/build/outputs/apk/debug/app-debug.apk`。`ANDROID_HOME` に SDK の場所を入れておく
（足りない SDK Platform は初回に自動で入る）。

## つながらないとき

まず同じスマホのブラウザで `http://<CubeのIP>:8080/` を開く。

- **ブラウザで開けてアプリで開けない** → アプリ側。メニューの「接続先を変更」で、
  実際に使っている URL を確かめる
- **ブラウザでも開けない** → Cube かネットワーク側。スマホがモバイル回線になっていないか、
  Cube の IP が DHCP で変わっていないかを疑う
