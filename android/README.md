# 電力モニタ (Android)

ダッシュボードをアドレスバーなしの全画面で開くだけのアプリ。

Chrome は HTTPS のページしか「アプリとしてインストール」できないため、
平文 HTTP の Cube ではホーム画面に追加してもアドレスバーが残る。
その一点を解決するためだけに存在する。

## 中身

依存ライブラリはゼロ。AndroidX も使っていない。

WebView 1枚に2つのページを出し分ける。

- **家にいるとき**: Cube のダッシュボードをそのまま表示する。あれは5秒ごとに
  自分で更新する完成したページなので、アプリ側で作り直すものは何もない
- **外にいるとき**: 届く相手がいないので、手元に貯めた履歴を
  `assets/history.html` で表示する

どちらを出すかは **Cube に `/healthz` を投げて決める**。Wi-Fi の名前を読む
方式だと位置情報の権限が要るうえ、「繋がっているか」ではなく「Cube が生きて
いるか」の方が知りたい事実そのものなので、こちらを選んだ。

### 履歴を貯める

`JobScheduler` の定期ジョブ（15分間隔、Wi-Fi のときだけ、再起動後も継続）が
Cube から引いて SQLite に入れる。アプリを開いたときにも1回走る。

常駐サービスにはしていない。通知が出っぱなしになるし、数分に1回の
HTTP リクエストのために前面サービスを張るのは釣り合わない。

| 取るもの | Cube 側の保持 | 意味 |
|---|---|---|
| 30分ごとの使用量 | 400日分（ディスク） | 長期の記録。月1回の同期でも欠けない |
| 分ごとの電力 | 24時間分（メモリ） | 直近の細かい動き。毎日同期しないと穴があく |

初回だけ400日分を取り、以降は直近10日分だけ取り直す。それより前は変わらない。
分ごとの値は端末側で90日経つと消す。

### CSV

戻るボタンのメニューから書き出す。保存先はシステムのファイル選択に任せるので、
ストレージ権限は要らない。

- 30分ごと: `date, slot, time, use_kwh, cum_kwh`
- 分ごと: `epoch, iso_local, power_w, current_r_a, current_t_a`

### 外から「今何W」は見られない

設計上そうなっている。外にいるときに見えるのは、**最後に家にいた時点までの
履歴**。リアルタイムを外で見るにはクラウド中継が要るが、それは採っていない
（Cube に TLS があるか不明、NAS の仕様も未確認、どちらも PC が無いと進まない）。

### 設定

戻るボタンでメニューが出る。画面に設定ボタンを置くとダッシュボードの
レイアウトに割り込むため。

## 受け取り方

`claude/android-apk` ブランチへの push で GitHub Actions が走り、
`cubej1-monitor-apk` という成果物に APK が入る。Actions のページから
ダウンロードできる。

デバッグ署名なので、そのままインストールできる。ただし提供元不明の
アプリの許可は必要。

## 手元でビルドする場合

```
cd android
gradle assembleDebug     # または Android Studio で開く
```

出力は `app/build/outputs/apk/debug/app-debug.apk`。

## つながらないとき

まず同じスマホのブラウザで `http://<CubeのIP>:8080/` を開く。

- **ブラウザで開けてアプリで開けない** → アプリ側。接続先の欄は URL ごと
  貼り付けても受け付ける（`http://` もポートも取り除いて解釈する）。
  エラー画面に、実際に使った URL と WebView のエラーコードが出る
- **ブラウザでも開けない** → Cube かネットワーク側。アプリは無関係。
  スマホがモバイル回線になっていないか、Cube の IP が DHCP で変わって
  いないかを疑う

## 設定

初回起動で Cube の IP を聞かれる。ポートの既定は 8080。
IP が分からなければリポジトリ直下の `find-cube.ps1` で探せる。
DHCP で IP が変わると接続できなくなるので、ルーターで固定しておくこと。
